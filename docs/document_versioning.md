# Стратегия изменения версии JSON-документа

## Цель

Обеспечить возможность изменения структуры JSONB-документов
новостного агрегатора без потери данных.

## Версия 1

Документ содержит плоскую структуру:

- schema_version — номер версии (1)
- title — заголовок новости
- text — текст новости
- source_id — идентификатор источника

## Версия 2

Структура документа изменена:

- schema_version — номер версии (2)
- title — заголовок новости
- content.body — текст новости
- content.language — язык новости
- source.id — идентификатор источника
- tags — массив тегов

## Стратегия миграции

1. Перед массовой миграцией создать резервную копию данных.
2. Добавить поддержку чтения документов обеих версий.
3. Новые документы создавать в актуальной версии.
4. Существующие документы постепенно переводить на версию 2.
5. При миграции сохранять исходные значения заголовка,
   текста новости и идентификатора источника.
6. Проверять обязательные поля после преобразования.
7. После завершения миграции отключить поддержку старой версии.

## Повторный запуск

SQL-скрипт обрабатывает только документы версии 1.
Документы версии 2 повторно не преобразуются.

## Откат

Для отката рекомендуется использовать резервную копию.
Обратная миграция также возможна, если новые поля версии 2
не содержат информации, отсутствовавшей в версии 1.

## Реализация в проекте

SQL-файл: sql/lab_document_versioning.sql

Таблица: lab_json.news_documents

На трёх реальных новостях успешно выполнена миграция
с версии 1 на версию 2.

Основная таблица dev.news не изменялась.
